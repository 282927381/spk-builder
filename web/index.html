③ 构建方式

把要安装的文件放到一个目录里(如 bin/、ui/、conf/),填下面的“源目录”。多架构时可在源目录下按 x86_64/ armv7/ arm64/ 建子目录放各自二进制。目录里如有 scripts/ 或 PACKAGE_ICON*.PNG 会被自动采用。

Docker 构建:源码挂载到 /src,产物目录挂载到 /out。请把你的最终可执行文件写到 $OUT_BIN(即 /out/bin/<binary_name>)。

在本机执行命令,命令应把最终可执行文件输出到 %OUT_BIN%(Windows)或 $OUT_BIN(Linux),可用环境变量 ARCH 区分架构。

spksrc 需在 WSL2 的 Linux 环境里运行。先在 WSL2 里 git clone https://github.com/SynoCommunity/spksrc,再填下面参数。架构映射:x86_64→x64、arm64→aarch64、armv7→armv7。

📖 使用说明


        
这是什么

        
SPK 构建台是一个本地可视化工具,用于打包 / 构建群晖(Synology)套件 .spk,并支持拆包分析、修改后二次打包。产物可直接丢进 sspks 套件服务器分发。


        
快速开始(打包一个纯脚本 / 静态目录)

        
    
          
  1. 「构建」页填 ① 套件信息(名称、版本为必填);
    2. 
          
  2. 勾 ② 目标架构(纯脚本/静态选 noarch);
    3. 
          
  3. ③ 构建方式选「预编译 / 纯脚本」,源目录填你要打包的文件夹(内含 bin/、ui/、conf/ 等);
    4. 
          
  4. 点「🚀 开始打包」,下方看日志,完成后点下载 .spk。
    5. 
        


        
五种构建方式

        
    
          
  • 预编译 / 纯脚本:已有二进制或脚本,直接打包,无需工具链;
    • 
          
  • Go:本机 Go 交叉编译(需安装 Go),生成静态二进制;
    • 
          
  • Docker:在容器里编译 C/C++ 等(需 Docker Desktop);
    • 
          
  • 本地命令:任意语言,自定义命令输出到 %OUT_BIN%;
    • 
          
  • spksrc:SynoCommunity 交叉编译框架(需 WSL2 + Ubuntu)。
    • 
        


        
解包与二次打包

        
    
          
  1. 「解包」页上传或填 .spk 路径,点解包;
    2. 
          
  2. 工具自动拆包、解析 INFO,并把元信息回填到构建表单;
    3. 
          
  3. 自动跳到「构建」页,改字段后直接点构建即二次打包(scripts/图标/conf 原样保留)。
    4. 
        


        
常见问题

        
    
          
  • 顶部徽标显示 Go / Docker 未安装:不影响「预编译/纯脚本」打包;只有用对应构建方式时才需要安装。
    • 
          
  • DSM 7 手动安装第三方包失败:套件中心设置里把「信任级别」改为「任意发布者」。
    • 
          
  • spksrc 报 WSL 不可用:管理员 PowerShell 运行 wsl --install -d Ubuntu,并在 Ubuntu 里 git clone https://github.com/SynoCommunity/spksrc。
    • 
          
  • 运行身份 root / 非 root:构建页「④ 运行配置」里选。选「非 root」会生成 conf/privilege 让 DSM 创建专用用户运行(DSM 7 推荐);选「root」则以最高权限运行。
    • 
          
  • 启动提示端口被占用:说明已有实例在运行,直接用提示的地址打开即可。
